# Threads 예약 발행

작업 폴더는 이 레포 루트다. `ungchun/thread-images` 리포 자체이고,
예약·본문·미디어가 전부 커밋되므로 기기가 달라도 같은 상태를 본다.
토큰은 GitHub Secrets에만 있고 실제 발행은 Actions가 30분마다 한다.

```
items.json            프로젝트 > 아이템 > 라운드 정의. 이 스킬의 단일 출처
schedule.txt          예약 목록 (탭 구분)
texts/                발행 전 본문. --- 아래가 답글
images/               발행 전 미디어
done/, done/images/   발행 끝난 본문·미디어
accounts/<계정>/      meta.txt(국가 타임존), reply.txt(트레이스 고정 답글)
run.py                러너. Actions가 부른다
check.py              전 계정 토큰 실검사
```

## 절대 원칙

발행은 되돌릴 수 없다. **전수조사를 통과하고 사용자 승인을 받기 전에는 절대 푸시하지 않는다.**
하나라도 걸리면 멈추고 무엇이 왜 걸렸는지 보여준다. 임의로 판단해 넘어가지 않는다.

## 흐름

### 1. 계정 상태 먼저 확인

계정을 고르게 하기 **전에** 반드시 상태를 알린다. 블락·만료된 계정이 있을 수 있다.

```bash
python3 check.py
```

토큰이 Secrets에만 있는 계정은 로컬에서 안 된다. 그때는 워크플로로 돌린다.

```bash
gh workflow run check.yml -R ungchun/thread-images
```

`dashboard.json`의 `errors` 필드도 함께 본다. 최근 발행 실패가 잡혀 있다.

```
계정 상태 확인했습니다. (토큰 실검사)

  정상 24개
  문제 1개
    haru._81a (일본2) — 토큰 만료. threads.com 로그인 필요
                        09/12 이후 3건 발행 실패 중
```

### 2. 프로젝트 선택

`items.json`의 `projects`를 읽어 보여준다.

```
어떤 프로덕트 올릴까요?
1. 트레이스
2. 문라이트
3. 코르텍스
```

### 3. 아이템 선택

그 프로젝트의 `items`를 최근 라운드와 함께 보여준다.

```
문라이트 — 어떤 홍보?
0. 새로 추가
1. 논문 번역 (최근 R02, 09/12 발행)
2. 레이아웃 유지 번역 (최근 R03, 09/13 발행)
```

`0. 새로 추가`면 이름·소재·링크 정책·본문·답글·미디어를 받아 items.json에 새 아이템을 만든다.

### 4. 세트 확인 — 그대로 갈지 고칠지

최신 라운드의 구성을 보여준다. **성과 수치는 보여주지 않는다.**

```
레이아웃 유지 번역 · R03 (09/13 발행)

본문   17개 언어. 한국어: "나 왜 이제야 이걸 알았지! 대체 어떻게 번역하고도…"
답글   17개 언어. ko·ja·tw·fr·de·es 자국 경로, 나머지 11개는 /en
미디어 본문에 영상 1개. 6개 언어(kr jp tw fr de es), 나머지는 es 폴백

그대로 갈까요, 고칠까요?
1. 그대로
2. 수정
```

**그대로**를 고르면 과거 발행 이력과 대조해 경고한다.

```
이 세트는 09/13에 24계정으로 이미 나갔습니다.
같은 계정에 같은 글이 또 올라갑니다. 진행할까요?
```

**수정**이면 무엇을 바꿀지 묻는다. 안 고른 것은 그대로 가져간다.

```
뭘 바꿀까요? (여러 개 가능)
1. 본문
2. 답글
3. 미디어
```

### 5. 본문·답글 수정

본문은 한국어로 받고 나머지 16개 언어는 번역한다. 사용자가 주요 언어를 직접 주면 그대로 쓴다.

답글은 아이템의 기본 문구를 제안하고 바꿀지 묻는다. 링크 경로 정책은 items.json이 단일 출처다.

번역했으면 **반드시 번역 검사**를 한다 (아래 전수조사 B 참조).

### 6. 미디어 수정

파일명 규칙을 사용자에게 요구하지 않는다. 그냥 올리게 하고 말로 설명받는다.

```
미디어 올려주세요. 이미지든 영상이든 그냥 올리시고,
어디에 어떤 순서로 들어갈지 말로 알려주세요.

예를 들면
  "이미지1 — 본문에 넣을 이미지"
  "영상1, 이미지2, 이미지3 — 답글에 순서대로"
  "이미지1~6 — kr jp tw fr de es 순서, 나머지 나라는 es로"
```

받으면 판정 결과를 보여주고 확인받는다.

```
받았습니다.

본문 미디어 (나라별)
  kr → 이미지1    jp → 이미지2    tw → 이미지3
  fr → 이미지4    de → 이미지5    es → 이미지6
  나머지 19계정 → 이미지6 (es 폴백)

이대로 갈까요?
```

파일명은 스킬이 규칙에 맞게 붙여 폴더에 넣는다. 언어 코드는 items.json `_언어코드`의 **표준**을 쓴다.

영상은 코덱을 반드시 확인한다. HEVC면 Threads가 거부하므로 H.264로 변환한다.

```bash
ffprobe -v error -select_streams v:0 -show_entries stream=codec_name,width,height -of csv=p=0 <파일>
ffmpeg -y -i <원본> -c:v libx264 -profile:v high -pix_fmt yuv420p \
  -vf "scale=trunc(iw/2)*2:trunc(ih/2)*2" -crf 20 -preset slow -movflags +faststart <출력>
```

### 7. 계정 선택

문제 계정을 기본으로 빼지 않는다. 있다는 걸 알리고 포함할지 고르게 한다.

```
계정 어디로?
0. 정상 24개
1. 전체 25개 (문제 계정 포함)
2. 개별 선택
3. 특정 나라만
```

### 8. 시각 결정

`items.json`의 `_시각기본값`을 제안한다. 같은 나라 2번째는 +간격, 3번째는 +간격x2.

```
문라이트 기본값은 현지 오전 11시입니다.
같은 나라 2번째 계정은 +30분, 3번째는 +1시간.

날짜만 정해주세요. (예: 9/20 토요일)
```

**요일은 반드시 현지 날짜 기준으로 센다.** UTC로 보면 미국·브라질이 하루 넘어가 착시가 생긴다.

```python
from datetime import datetime, timedelta
from zoneinfo import ZoneInfo
local = datetime(Y, M, D, 시, 분, tzinfo=ZoneInfo(계정타임존)) + timedelta(minutes=간격*n)
utc = local.astimezone(ZoneInfo("UTC"))
```

### 9. 전수조사

**여기를 대충 하면 안 된다.** 아래 항목은 전부 실제로 사고가 났던 것들이다.

#### A. 파일·구성

- 본문 파일이 고른 계정 전부에 존재하는가
- 미디어 파일이 로컬에 존재하는가
- 답글이 비어 있지 않은가
- 답글 길이가 500자 이하인가 — 초과하면 답글만 거부되고 본문이 중복 발행된 적 있다
- 스포일러(`||`) 표시가 의도대로인가
- `media:` 줄이 올바른가 (`-`면 답글 미디어 없음)

#### B. 번역 검사 (새로 번역했을 때 필수)

- 언어 판정 — 본문 언어가 계정 국가와 맞는가. 대만에 간체, 브라질에 포르투갈 문체가 섞이면 안 된다
- 문체 구분 — pt(tu·podes) / br(você), es(vosotros) 구분
- 링크 존재 — 답글에 링크가 있는가, 경로가 정책과 맞는가
- 이모지 — 원문에 있으면 번역본에도 있는가
- **의미 대조** — 각 언어를 한국어로 역번역해 원문 의미와 맞는지 본다.
  실제로 말레이어 "느림"을 "kelembapan(습도)"으로, 태국어 "대체품"을 "대리인"으로 쓴 오역을 이 방법으로 잡았다

#### C. 중복

- 예약 안에서 같은 계정이 두 번 들어갔는가
- 같은 계정에 같은 본문이 배정됐는가
- **과거 발행 이력과 같은 본문인가** — `done/`과 dashboard.json 본문을 대조
- 기존 예약과 같은 계정이 1시간 이내로 겹치는가

#### D. 교차 오염

- 코르텍스·문라이트 본문에 트레이스 앱스토어 링크가 섞이지 않았는가
- 프로젝트가 다른 링크가 들어가지 않았는가

run.py는 본문에 인라인 답글이 있으면 계정 고정 답글(`reply.txt`)을 쓰지 않는다.
트레이스만 고정 답글을 쓰고, 코르텍스·문라이트는 본문 파일 안 답글을 쓴다.

#### E. 원격 서빙

파일이 로컬에 있어도 푸시 전이면 발행 때 못 가져온다. raw URL을 실제로 찔러본다.

```bash
curl -s -o /dev/null -w "%{http_code}" \
  "https://raw.githubusercontent.com/ungchun/thread-images/main/images/<경로>"
```

#### F. 시각

- 현지 시각이 프로젝트 기본값과 맞는가
- 같은 나라 2·3번째 간격이 맞는가
- **현지 날짜 기준** 요일이 의도대로인가

#### G. 실험 조건

- A/B를 돌리면 같은 날 같은 시각인가. 요일이 같이 바뀌면 비교가 무의미하다
- 이번에 바뀌는 변수가 몇 개인가. 둘 이상이면 경고한다

8라운드 동안 문구 판정을 한 번도 못 낸 이유가 매번 변수를 두 개 이상 바꿨기 때문이다.
상세는 `rounds.json`의 `실패기록`을 읽는다.

#### 결과 표시

```
전수조사

파일      본문 24개·미디어 6개 전부 존재
번역      언어 판정 24/24, 링크 24/24, 의미 대조 이상 없음
중복      계정 중복 0, 같은 본문 0, 과거 발행과 중복 0
교차      프로젝트 링크 섞임 0

시각      현지 11:00 기준, 2·3번째 +30/+60분
충돌      기존 예약과 1시간 이내 겹침 0
실험      바뀐 변수 1개 (미디어)

한국시간      현지   국가 계정          본문       미디어
09/20 10:00  11:00  AU  elle__jm     ml03_en    ml03_es.mp4

```

### 10. 커밋·푸시

승인을 받은 뒤에만 한다.

```bash
git add -A && git commit -m "<프로젝트> <아이템> R<n> 예약 (<날짜>, <계정수>건)"
for i in 1 2 3; do git push -q && break; git pull --rebase --autostash -q; sleep 3; done
```

푸시 후 items.json에 새 라운드를 기록한다. 수정해서 올렸으면 라운드가 하나 늘어난다.

```
푸시 완료. 첫 발행은 09/20 10:00 (한국시간)입니다.
마지막이 09/21 03:00에 나갑니다.

발행이 끝나면 결과를 점검하세요. 본문·답글이 다 나갔는지 봅니다.
```

### 11. 발행 후 확인

주말에 답글 8건이 링크 없이 나간 적이 있다. 발행 후 확인이 없어서 늦게 발견됐다.

```bash
gh run list -R ungchun/thread-images -w post.yml --created "<시작>..<끝>" -L60 \
  --json databaseId -q '.[].databaseId' | while read id; do
  gh run view $id -R ungchun/thread-images --log 2>/dev/null | grep -E "posted|REPLY-FAIL|FAIL |SKIP"
done
```

`REPLY-FAIL`이 있으면 그 게시물에 답글이 안 달렸다. run.py가 다음 회차에 자동 재시도하지만
계속 실패하면 수동으로 달아야 한다.

## 함정

**발행은 되돌릴 수 없다.** Threads API로 게시물·답글 삭제가 안 된다. 앱에서 직접 지워야 한다.

**중복 발행 방어는 세 겹이다.** 같은 회차 안에서는 `done` 표시, 회차 간에는 schedule.txt 갱신,
회차 겹침은 post.yml의 concurrency 가드가 막는다. 이 구조를 깨뜨리는 수정을 하지 않는다.

**푸시가 거부되면 중복이 난다.** schedule.txt가 갱신되지 않아 30분 뒤 회차가 같은 글을 또 올린다.
post.yml이 5회 재시도하고 실패 시 에러를 낸다.

**언어 코드가 파일마다 어긋나 있다.** 한국이 이미지는 `ko` 텍스트는 `kr`, 말레이시아가 `my`와 `ms`,
미국이 `en`과 `us`로 섞여 있다. items.json `_언어코드`의 표준·별칭으로 흡수한다.

**발행이 끝나면 파일이 done/으로 옮겨진다.** 과거 라운드를 찾을 때는 `texts/`와 `done/` 양쪽을 본다.
`intro.`·`shared.`로 시작하는 파일은 재사용 자산이라 옮기지 않는다.

**계정 토큰을 출력하지 않는다.** 대화에 붙이지도 않는다.

**죽은 계정도 기본으로 포함한다.** 빼는 판단은 사용자가 한다. 상태만 알린다.
