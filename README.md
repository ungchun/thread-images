# thread-images

Threads 홍보 자동화. 트레이스·문라이트·코르텍스 세 제품을 18개국 25개 계정에 예약 발행하고,
답글에 대응하고, 성과를 모은다.

예약·본문·미디어가 전부 이 레포에 커밋되므로 기기가 달라도 같은 상태를 본다.
토큰은 GitHub Secrets에만 있고 실제 발행은 Actions가 한다.

## 시작하기

```bash
git clone https://github.com/ungchun/thread-images
cd thread-images && claude
```

그 폴더에서 클로드 코드를 열면 `.claude/skills/`의 스킬이 잡힌다.
`/threads`로 발행, `/threads-reply`로 답글 대응.

토큰은 받을 필요 없다. 발행은 Actions가 Secrets로 하므로 레포 협업자 권한만 있으면 된다.
`gh auth login`만 해두면 워크플로를 부를 수 있다.

## 구조

```
items.json          프로젝트 > 아이템 > 라운드. 발행 스킬의 단일 출처
rounds.json         실험 기록. 2026-09-14에 전부 확정으로 닫혔다
schedule.txt        예약 목록 (탭 구분: UTC시각·계정·본문·스레드미디어·인스타미디어)
texts/              발행 전 본문. `---` 아래가 답글
images/             발행 전 미디어
done/, done/images/ 발행 끝난 것
accounts/<계정>/    meta.txt(국가 타임존), reply.txt(트레이스 고정 답글)
research/           나라별 포맷 조사, 시장 조사, 주말 전수조사 보고서
```

```
run.py           러너. 예약 시각이 지난 줄을 발행한다
dashboard.py     성과 수집 → dashboard.json
notion_sync.py   문라이트·코르텍스 성과를 노션 DB에 upsert
replies.py       답글 조회·발행·숨김
check.py         전 계정 토큰 실검사
report.py        트레이스 성과를 슬랙으로
serve.py         대시보드 로컬 서버 (localhost:8899)
```

## 자동으로 도는 것

GitHub Actions는 자체 cron을 쓰지 않는다. cron-job.org가 workflow_dispatch로 깨운다 —
스케줄러가 회차를 통째로 흘리는 일이 두 번 있어서 옮겼다.

| 언제 | 무엇 | 워크플로 |
|---|---|---|
| 30분마다 | 예약 발행 | post.yml |
| 매일 08:00 KST | 노션 동기화 (문라이트·코르텍스) | notion-sync.yml |
| 매일 10:00 KST | 슬랙 홍보 브리핑 (트레이스) | report.yml |
| 수동 | 성과 수집 / 답글 / 토큰 점검 | dashboard.yml, replies.yml, check.yml |

앱 매출 브리핑(08:00 슬랙)은 이 레포가 아니라 `corca-ai/trace-analytics`에 있다.

## 발행 흐름

`/threads`를 부르면 이 순서로 간다.

계정 상태 확인 → 프로젝트 → 아이템 → 세트(그대로/수정) → 계정 → 오전·오후 선택 →
전수조사 → 승인 → 푸시 → 발행 후 확인.

**전수조사를 통과하고 승인을 받기 전에는 푸시하지 않는다.** 발행은 되돌릴 수 없다 —
Threads API로 게시물·답글 삭제가 안 되고 앱에서 직접 지워야 한다.

## 중복 발행 방어 (세 겹)

한 번 무너진 적이 있어서 세 겹으로 막아뒀다. 이 구조를 깨뜨리는 수정을 하지 않는다.

- 같은 회차 안: `done` 표시. 답글이 실패해도 본문은 한 번만 나간다
- 회차 간: schedule.txt 갱신. 푸시가 거부되면 5회 재시도하고 실패 시 워크플로를 실패시킨다
- 회차 겹침: post.yml의 concurrency 가드. 앞 회차가 도는 동안 새 호출은 대기한다

답글 발행이 실패하면 3회 재시도하고, 그래도 안 되면 예약 줄에 `done:reply-threads:<id>`를
남겨 다음 회차가 답글만 다시 민다. 성공해야 줄이 지워진다.

## 실험은 끝났다

2026-09-14에 문구·시각·요일 실험을 전부 닫았다. 여덟 라운드를 돌렸으나 문구 A/B는
판정 불가였다 — 요일과 시각을 동시에 고정한 라운드가 하나도 없었다.

이제 문구는 고정 변수다. 그 나라에서 터진 포맷을 그대로 쓰고 A안·B안으로 쪼개지 않는다.
시각은 `items.json`의 `_시각기본값`(프로젝트별 오전·오후)이 단일 출처이고, 요일은
발행 편의로 정한다. 근거는 `rounds.json`의 `확정` 섹션에 있다.

실험을 다시 열자는 제안이 나오면 그 섹션의 `문구_AB`·`시각`·`요일`을 먼저 읽는다.

## 알아둘 것

**계정 토큰을 출력하거나 대화에 붙이지 않는다.**

**언어 코드가 파일마다 어긋나 있다.** 한국이 이미지는 `ko` 텍스트는 `kr`,
말레이시아가 `my`와 `ms`, 미국이 `en`과 `us`. `items.json`의 `_언어코드`가 표준·별칭으로
흡수한다.

**영상은 H.264여야 한다.** HEVC면 Threads가 거부한다.

**raw.githubusercontent.com에 5분 캐시가 있다.** 이미지를 갈아끼운 직후엔 옛 파일이
내려올 수 있다.

**대시보드는 `serve.py`로 띄운다.** 파일을 직접 열면 캐시 때문에 옛 화면이 남는다.
